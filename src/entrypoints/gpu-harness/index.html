GPU harness (debug tool)

Runs one fixed English paragraph through the CPU backend and several WebGPU configurations of the on-device model, then compares the outputs. Used to diagnose garbled WebGPU output on Android. This page is not part of the translation product.

Model

Harness only: the translation product keeps its own model. Each model is downloaded from a pinned Hugging Face commit (size and sha256 checked), stored separately, and runs with its own prompt format; decoding is greedy with the same token limit for every model. The PLaMo 3 0.8B file is the one the options page manages.

Translation runs

"Run harness" runs every config on this page, one after another. "Run all isolated" reloads the page for each config (fresh page, wllama worker and WebGPU device), so a config cannot affect the next one; results are kept in this tab until cleared. "Run alone" does the same for one config (plus the CPU reference if none is saved).

Results

GPU performance

Each config runs in a fresh page (fresh worker and WebGPU device): model load, then the prompt twice with the prompt cache off (run 1 includes shader compilation, run 2 is warm), with llama.cpp's prompt/decode timings and ggml-webgpu's per-token counters. "GPU perf breakdown" runs the chosen config (plus a per-op timing run when the box below is ticked; that run submits after every op and crashed the page on Adreno). "Run GPU perf sweep" runs every config below except the hybrid ones, CPU baseline first, with no per-op runs. Each config is cut off after 5 minutes; a crash or device loss only ends that config. Copy the report text and paste it back.

"Titles vs paragraph" runs the production translation pipeline (planner, PLaMo line packing, scheduler waves on the slots, prompt cache as in the extension) for 12 short titles packed as page blocks, the same 12 titles one request each (as headings), and one long paragraph, on cpu, cpu-2-slot, gpu-r6-r4-1-slot, gpu-r6-r4 (2 slots, the Adreno default) and gpu-r6-r4-4-slot, one config per page load. It reports the wall time, the first finished block and every request (start, ttft, prompt and decode timings).
